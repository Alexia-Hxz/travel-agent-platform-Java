## 0. 一句话结论

原项目后端 = **39 条 HTTP 路由**（你要求的 38 个业务端点 + 1 个健康检查）、**6 张表**、**两条纯线性流水线（6 节点 / 4 节点）**、**20 个确定性工具模块**、**一套手写向量检索（按行切分 + 1024 维 + 余弦）**。
这些全部可以 1:1 落到 `Java 17 + Spring Boot 3 + MyBatis-Plus + Flyway + Spring Security(JWT 过滤器) + Milvus + MySQL 8`，**前端 70 个文件一行不改**。
唯一真正需要你拍板的是 5 个技术选型（R1–R5），其中 **R2（OCR）与 R3（数据库）** 决定返工量最大。

## 3. 契约细则（最容易漏的 12 条）

1. **snake_case**：`spring.jackson.property-naming-strategy=SNAKE_CASE`。
2. **时间格式**：`WRITE_DATES_AS_TIMESTAMPS=false`，并**逐个类型注册固定序列化器**：
   - `LocalDate` → `yyyy-MM-dd`
   - `LocalTime` → **`HH:mm:ss`**（关键：Java 默认 `ISO_LOCAL_TIME` 会把 `09:00:00` 写成 `09:00`，前端与调整逻辑按 `[:5]`/字符串比较，必须补零到秒）
   - `LocalDateTime` → `yyyy-MM-dd'T'HH:mm:ss`（原 Pydantic 输出无时区、无毫秒）
3. **null 必须输出**：Jackson 不得配 `NON_NULL`。原响应里 `note:null`、`image_url:null`、`hotel:null` 都在。
4. **错误体**：`{"detail": "..."}`。禁止 Spring 默认 `{timestamp,status,error,path}`；`@RestControllerAdvice` 统一包。401 另带 `WWW-Authenticate: Bearer`。
5. **参数校验失败**：FastAPI/Pydantic 的 422 是 `{"detail":[{"type","loc","msg","input","url"}]}`。前端 `readDetail()` 只认 string，两种都能跑。我按 **FastAPI 的数组结构**输出（`loc` 用 `["body","字段名"]`），保证"逐字节"路径存在。
6. **枚举小写**：`PlaceType`、`parse_status`、`index_status`、`adjustment.status`、`VisionDocumentType` 全部 `@JsonValue`/`@JsonCreator`，禁止大写。
7. **枚举值域**：`parse_status ∈ {pending,processing,completed,failed}`；`index_status ∈ {pending,indexed,skipped,failed}`；`adjustment.status ∈ {pending,applied,rejected}`。
8. **`ItineraryItemRead` 内嵌完整 `place`**：必须 join 出来，缺失会前端崩。
9. **`place_recommendations` 是白名单**（源码 `_compose` 里 30 个字段逐一列出）。Java 必须用同名字段的 DTO，绝不能直接把内部 Map 返回；`price_pending` 固定 `false`。
10. **`recommendations` / `sources`** 只暴露 `PlanSource` 的 6 个字段（`source_type,title,url,snippet,score,image_url`），内部 `web_results` 的多余键要丢弃。
11. **204 无 body**；`DELETE /places` 是 **200 + `{"removed":n}`**（不是 204）。
12. **`apply` 的返回**：`itinerary_item_ids` 是**应用后整趟行程的全部 item id**（源码 `apply_adjustment` 返回 `list_itinerary_items(trip_id)`，不是"新增的那些"）。这一点必须照抄，否则前端高亮的行数不对。

补充：CORS 只放 `http://localhost:5173` 与 `http://127.0.0.1:5173`，`allow_methods=*`、`allow_headers=*`。

## 8. 关键算法与数值（对齐清单）

1. **预算公式**（`budget.py`）
   - `hotel`：`level×260×max(1, days-1)`；`restaurant`：`level×80×days×people`；`airport/station`：`level×30`；其它：`level×100`
   - 行程版：`unit_price×quantity`，`hotel` 单位"晚"、`restaurant`"次"；`transport=60×days` 单列；`daily_estimate=round(total/days)`
   - 无 place 时：`total=60×days`；住宿 300×nights、餐饮 80×days×people **只出现在 `excluded_allowances`**（不计入总额）
2. **最大余数法**（`budget_plan._split`）：`int()` 截断 → 余数按小数部分降序、循环补齐，行和恒等于 total。
3. **Python `round()` 是银行家舍入**：`round(x)`/`round(x,4)` 必须用 `BigDecimal HALF_EVEN`，否则 `daily_estimate`、`share`、`similarity` 会差 1。同理 `int(round(x))`。
4. **价格守卫**（`recommendations`）：`PRICE_BOUNDS` 分类上下限、`FOREIGN_LOCAL_THRESHOLDS`、`_plausible_unit_price`（疑似"日元当人民币"时按汇率换算）、免费标记识别、低于当地下限时抬到 `realistic_floor` 并置 `price_adjusted=true`。
5. **冲突检测**：同一天内按开始时间排序，`second.start >= first.end` 即 break（只与相邻窗口比较）。
6. **自动排期**（`auto_schedule`）：日窗 09:00–21:00、时长 attraction 2h / restaurant 1.5h / hotel·airport·station 1h；从 `preferred_date` 起试，30 分钟步进；放不下进 `skipped` 并给原因；`already_scheduled` 收集已排名字。
7. **文档切分**（`vector_service.split_document`）：目标 420 字、重叠 60 字、按行对齐、超长行按 `target-overlap` 步长切；`MIN_INDEXABLE_CHARS=40` 拒绝索引；零宽字符剔除；保留 `char_start/char_end`。
8. **嵌入**：`text-embedding-v4`、1024 维、**每批 ≤10**、按 `index` 重排、数量/维度校验、单条截断 4000 字。
9. **检索**：`n_results = min(limit, 20, 该 trip 已存条数)`；余弦 → `similarity = 1 - distance`，`round(...,4)`；`status ∈ ok/empty/unavailable/failed/skipped`，空结果必带 `reason`。
10. **天气**：16 天窗；`indoor = code>=51 || 降水>=60 || 风速>=45`；超出窗口按天给"还有 N 天"的具体文案；跨窗口截断并提示。
11. **图片**：`MAX_IMAGE_LOOKUPS=40`、`IMAGE_PHASE_BUDGET=60s`、探测 4s/6s、失败缓存 600s、`MAX_BYTES=2MB`、缓存文件名 `sha256(url)`、`Cache-Control: public, max-age=31536000, immutable`。
12. **`_same_venue`**：去空格小写后互为子串且差异部分非纯数字 → 同一地点（"蒋有记" vs "老门东内蒋有记"）。

## 9. 风险与推荐方案（**等你确认**）

### R1 — `enable_search` 透传
- **A（推荐）自建 `DashScopeChatClient`（WebClient 直调兼容模式）**，`enable_search` 作为 JSON 顶层字段发送。
  理由：原实现本来就是裸 `openai` SDK + `extra_body`；各调用点的超时/模型/`max_tokens`/`response_format` 完全不同（30s/90s/20s/60s/120s），Spring AI 的全局 `ChatOptions` 反而要逐调用覆写，且**无法保证私有字段透传**。功能等价优先级 > 框架纯度。
  代价：Spring AI 只用它的 `EmbeddingModel`（或连这个也自建，见 R5-B）。
- **B 严格按映射表用 Spring AI Alibaba**（`spring-ai-alibaba-starter-dashscope` + `DashScopeChatOptions.withEnableSearch(true)`）。
  代价：先写 20 行 spike 验证透传；社区版本与 Spring Boot 3.x / Spring AI 1.0 的版本矩阵要对齐；`enable_thinking:false`、`response_format` 需逐个验。
- **C A+B 混合**：对话走 A，Embedding 走 Spring AI `EmbeddingModel`。**这也是我推荐的最终形态**。

> 请选：**A / B / C**（我建议 C）。

### R2 — OCR
- **A（推荐）RapidOcr-Java（ONNX Runtime + PP-OCRv4 中英文模型）**：纯 Java、离线、与 PaddleOCR 同模型族，中文截图能识别（原版只有英文模型，中文本来就识别不了——这是"修好"而不是"阉割"）。
  代价：`onnxruntime` 依赖（~50MB）+ 模型文件（~15MB）；首次加载 1–2s；需要 det/rec/cls 三个模型。
- **B 多模态视觉模型替 OCR**（`qwen3-vl-flash` 已有链路）：零本地依赖、中文最好；但每次解析消耗 token、需联网、结果非确定性。
- **C ONNX Runtime 自实现 PP-OCR 前后处理**：等价度最高、工作量最大（DB 后处理 + CTC 解码 + 图像预处理，1000+ 行），不建议。
- **D 保留 Python OCR 子进程**：违反硬性约束 4，仅作对照。

> 请选：**A / B**（我建议 A；若你不接受 65MB 依赖，选 B）。

### R3 — 数据库
- **A（推荐）MySQL 8 + Flyway**：符合技术栈要求；`docker compose` 起库；老数据用一次性脚本迁移（6 张表，行数很小）。
  代价：本地要跑 MySQL（或 Docker）；`JSON` 列、`DATETIME` 精度、`FLOAT→DOUBLE` 需逐列核对；`created_at` 时区统一 UTC。
- **B SQLite + `sqlite-jdbc` + Flyway**：零迁移（直接复用 `backend/travel_agent.db`），行为最接近；但不满足映射表，并发写弱。

> 请选：**A / B**（我建议 A）。若选 A，我会额外给 `tools/sqlite2mysql.py`（读旧库 → 生成 `INSERT`）并保留 `backend/travel_agent.db` 只读不删。

### R4 — Token / 密码格式（**这个没有取舍空间，必须照抄**）
- 自实现：`base64url(payload).base64url(HMAC-SHA256(secret, body))`，`payload={"sub","iat","exp"}`、**紧凑分隔符**（`{"sub":1,"iat":...}`，无空格）、`urlsafe` 且**去掉 `=` 填充**。
- 密码：`scrypt$16384$8$1$base64(salt16)$base64(hash64)`，Bouncy Castle `SCrypt.generate`，`hmac.compare_digest` ≡ `MessageDigest.isEqual`。
- Spring Security 只用它的过滤器链/`SecurityContext`，**不产生 token**（否则老 token 全废、老用户登不上）。
- 验收：把 Python 侧生成的 3 个真实 token + 2 个真实哈希写成 JUnit 固定向量，Java 必须**双向**通过。

> 请确认「按此实现」（无需选型）。

### R5 — 向量库
- **A（推荐）Milvus 2.4 standalone**：collection `trip_documents`，主键 `chunk_id` VARCHAR，标量 `trip_id` INT64 + INVERTED 索引，向量 1024 维 `COSINE` + HNSW(M=16, efConstruction=200)，检索 `ef=64`。
  **关键差异**：Milvus 的 COSINE 返回的 `score` 就是余弦相似度（越大越像），**不是** `1-distance`；`similarity = round(score, 4)`。
  代价：多一个容器；HNSW 近似会让 0.525/0.285 有 ±0.005 波动 → 验收以 **12 问标注集 Recall@5 = 12/12、top-1 = 12/12** 为准，不以精确等值。
- **B MySQL 存 float32 BLOB + Java 精确余弦**：零额外服务、结果与 Chroma 数学上完全一致、可复现；约 200 行代码；但不满足"Milvus"要求，数据量大时全表扫（本场景千级片段，毫秒级）。
- **C Qdrant/Weaviate**：同样要多一个服务，收益不大。

> 请选：**A / B**（我建议 A；若本机不方便常驻 Milvus，B 是"数值最可复现"的退路）。

### R6（我额外发现的，必须一起处理）
`core/image_hosts.py` 会**改写 `socket.getaddrinfo`**：当 `images.pexels.com` 解析到不可连接的 IP 时，钉到可用边缘 IP。
Java 没有全局 DNS 钩子，等价做法是给图片用的 Reactor Netty `HttpClient` 单独装一个 `AddressResolverGroup`（先探原解析结果，不通再用 `IMAGE_HOST_FALLBACKS`）。
**不配置 `IMAGE_HOST_FALLBACKS` 时行为与原来完全一致（什么都不做）**。默认实现，不需要你选。
